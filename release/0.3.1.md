Do not squash, rebase, or use a synthetic merge. Stop if any command fails:


After the approved preparation PR is merged, resolve its actual merge commit
and verify the two-parent boundary against the captured base and live PR head:

```bash

BASE_SHA_FILE="${BASE_SHA_FILE:-/tmp/limitora-0.3.1-base-sha}"
```

## No-Go Gates and Recovery

- Missing or invalid ledger, wrong trusted-main bytes, wrong candidate SHA, or
  Candidate is not a strict ancestor of trusted main.
- Existing `v0.3.1` tag, PyPI `0.3.1` version, or GitHub Release; lightweight tag,
  PR head, direct main push, squash, rebase, synthetic merge. Do not tag or publish.
- Failed protected preflight, validation, artifact digest/hash/receipt/manifest,
  installed smoke, Wrong Pending Trusted Publisher, environment, tag policy,
  workflow identity, or OIDC publication failure.
- published files differ from the tag-run receipt, or publication would rebuild,
  use `skip-existing`, or use an unverified artifact.

Before publication, record the failed gate and abandon only this preparation branch. Never move/recreate a tag, overwrite a published file, or silently retry partial publication; preserve receipts and evaluate a corrective new version.
