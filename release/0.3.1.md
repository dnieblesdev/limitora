# Limitora 0.3.1 Release Preparation Dossier

**Status:** release preparation only. `0.3.1` is not published to PyPI, and a
GitHub Release does not yet exist. This dossier records the reviewed Codex
compatibility change, the candidate boundary, the ledger handoff, and the
protected publication controls.

## Release Notes

- PR #62, resolving issue #61, makes inbound Codex JSONL parsing structurally
  tolerant of additive metadata on valid server notifications.
- Correlated responses retain a strict envelope: unknown fields remain protocol
  failures, while valid notifications are discarded after structural checks.
- Notifications still require a non-empty string `method` and must not carry a
  response `result` or `error`; tests cover metadata, malformed shapes, and
  correlated error preservation.
- The Codex protocol documentation and hermetic tests record this compatibility
  boundary. No provider payload, credential, or private metadata is surfaced.
- The package remains dependency-free by default, with HTTPX only in the
  opt-in `opencode-go` extra, and compatibility remains Python 3.10-3.14 on
  Linux and Windows.

## Candidate Merge Boundary

Before this preparation PR is merged, verify that the trusted base is the
expected merge of PR #62 and capture it outside the repository. Do not squash, rebase, or use a synthetic merge. Stop if any command fails:

```bash
set -euo pipefail
BASE_SHA_FILE="${BASE_SHA_FILE:-/tmp/limitora-0.3.1-base-sha}"
git fetch origin main
base_sha="$(git rev-parse origin/main^{commit})"
EXPECTED_BASE_SHA="f665e26c5124afbf0c5c7c7aad495897a0d70176"
test "$base_sha" = "$EXPECTED_BASE_SHA"
test "$(git rev-parse origin/main^{commit})" = "$base_sha"
printf '%s\n' "$base_sha" > "$BASE_SHA_FILE"
```

After the approved preparation PR is merged, resolve its actual merge commit
and verify the two-parent boundary against the captured base and live PR head:

```bash
set -euo pipefail
BASE_SHA_FILE="${BASE_SHA_FILE:-/tmp/limitora-0.3.1-base-sha}"
: "${PREPARATION_PR:?set PREPARATION_PR to the approved release-preparation PR number}"
test -s "$BASE_SHA_FILE"
base_sha="$(cat "$BASE_SHA_FILE")"
[[ "$base_sha" =~ ^[0-9a-f]{40}$ ]]
test "$base_sha" = "f665e26c5124afbf0c5c7c7aad495897a0d70176"
test "$(git cat-file -t "$base_sha")" = commit
test "$(gh pr view "$PREPARATION_PR" --json state --jq '.state')" = MERGED
pr_head_sha="$(gh pr view "$PREPARATION_PR" --json headRefOid --jq '.headRefOid')"
merge_sha="$(gh pr view "$PREPARATION_PR" --json mergeCommit --jq '.mergeCommit.oid')"
git fetch origin main
git fetch origin "pull/$PREPARATION_PR/head"
test "$(git rev-parse FETCH_HEAD)" = "$pr_head_sha"
test "$(git cat-file -t "$pr_head_sha")" = commit
test "$(git cat-file -t "$merge_sha")" = commit

test "${#parents[@]}" -eq 2
test "${parents[0]}" = "$base_sha"
test "${parents[1]}" = "$pr_head_sha"
git merge-base --is-ancestor "$pr_head_sha" "$merge_sha"
git show "$merge_sha:pyproject.toml" | grep -Fx 'version = "0.3.1"'
```

The candidate merge must change only the approved release-preparation paths:

## Ledger Authorization Boundary

The final authorization must be a separate later trusted-main commit `T` that
directly follows candidate `M` and changes no path other than
`release/ledger.json`. Derive `M` from trusted-main history; do not accept a
fresh operator-supplied candidate SHA:

```bash
set -euo pipefail
: "${AUTHORIZATION_PR:?set AUTHORIZATION_PR to the approved ledger-only PR number}"
git fetch origin main
trusted_main_sha="$(git rev-parse origin/main^{commit})"
candidate_sha="$(git log --first-parent -1 --format=%H "$trusted_main_sha" -- release/0.3.1.md)"
EXPECTED_BASE_SHA="f665e26c5124afbf0c5c7c7aad495897a0d70176"
test -n "$candidate_sha"
test "$candidate_sha" != "$trusted_main_sha"
test "$(git cat-file -t "$candidate_sha")" = commit
git merge-base --is-ancestor "$candidate_sha" "$trusted_main_sha"
candidate_parents=($(git show -s --format=%P "$candidate_sha"))
test "${#candidate_parents[@]}" -eq 2
test "${candidate_parents[0]}" = "$EXPECTED_BASE_SHA"
candidate_paths=($(git diff-tree --no-commit-id --name-only -r "${candidate_parents[0]}" "$candidate_sha"))
test "${#candidate_paths[@]}" -eq 8
test "$(git show "$candidate_sha:pyproject.toml" | grep -Fx 'version = "0.3.1"')"
test "$(gh pr view "$AUTHORIZATION_PR" --json state --jq '.state')" = MERGED
test "$(gh pr view "$AUTHORIZATION_PR" --json baseRefName --jq '.baseRefName')" = main
authorization_merge_sha="$(gh pr view "$AUTHORIZATION_PR" --json mergeCommit --jq '.mergeCommit.oid')"
test "$authorization_merge_sha" = "$trusted_main_sha"
authorization_head_sha="$(gh pr view "$AUTHORIZATION_PR" --json headRefOid --jq '.headRefOid')"
parents=($(git show -s --format=%P "$trusted_main_sha"))
test "${#parents[@]}" -eq 2
test "${parents[0]}" = "$candidate_sha"
test "${parents[1]}" = "$authorization_head_sha"
git merge-base --is-ancestor "$authorization_head_sha" "$trusted_main_sha"
test "$(git diff-tree --no-commit-id --name-only -r "$candidate_sha" "$trusted_main_sha")" = "release/ledger.json"
test "$(git rev-parse "$candidate_sha:release/ledger.json")" != "$(git rev-parse "$trusted_main_sha:release/ledger.json")"
git show "$trusted_main_sha:release/ledger.json" | python -c 'import json, sys; d=json.load(sys.stdin); assert d == {"schema_version": 1, "version": "0.3.1", "source_sha": sys.argv[1]}' "$candidate_sha"
```

The final assertions are fail-closed: `T` must be the merged ledger-only PR,
its second parent must be that PR's live head, and its ledger must authorize
exactly version `0.3.1` and candidate `M`. Do not tag or publish if candidate
derivation, PR identity, parent, changed-path, ledger, or ancestry checks fail.

## No-Go Gates and Recovery

- Missing or invalid ledger, wrong trusted-main ledger bytes, wrong candidate
  SHA, or Candidate is not a strict ancestor of trusted main.
- Existing `v0.3.1` tag, PyPI `0.3.1` version, or GitHub Release.
- Lightweight tag, PR head, direct main push, squash, rebase, or synthetic
  merge; do not tag or publish from any of these states.
- Failed protected preflight, validation cell, artifact digest, hash, receipt,
  manifest, or installed smoke; Wrong Pending Trusted Publisher, environment,
  tag policy, or workflow identity; OIDC publication failure; published files differ from the tag-run receipt.
- Rebuild during publication, `skip-existing`, or an unverified artifact.

Before publication, record the failed gate and remove only uncommitted
preparation changes or abandon this release-preparation branch. Never move or
recreate a tag, overwrite a published file, or silently retry partial
publication. After partial publication, preserve receipts and evaluate a
corrective new version with the maintainer.
